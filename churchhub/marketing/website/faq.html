Help

Questions leaders ask first

Straight answers about hierarchy, money, security, and how a pilot works.

Is ChurchHub only for Adventist hierarchy?

ChurchHub models a multi-level church hierarchy (through to local church) and a denomination wall for SaaS. Terminology can be configured for a denomination. It is designed for institutional church networks — not a flat single-site club app.

Do we get a second set of accounting books?

No. Transactions are the books of record (double-entry). The ledger UI posts into those books. Corrections use reversing entries — not silent edits of posted journals.

Can a district pastor see every church’s data?

Only within authorized scope. Permissions and church hierarchy filters are enforced on the server. The UI never becomes the only control.

Is there a member-facing app?

Yes — a responsive member portal for login, profile, announcements, selected self-service flows, and live meeting join details. Staff use the full web workspace.

What about payroll and fixed assets?

Both exist as modules and can be enabled per church/tenant via the feature registry. Pilots often start with membership, treasury, and remittance first.

Is MFA required for everyone?

MFA capabilities are available and policy-configurable for privileged roles. Do not assume universal enforcement on every account unless your deployment policy turns it on.

Can we run ChurchHub in our own data center?

Yes. Reference stack includes Django, PostgreSQL, Redis, Celery, Gunicorn, and Nginx, with Docker/Compose production profiles and operational runbooks.

How do we migrate from spreadsheets?

Professional services can map chart of accounts and import members/transactions. Platform import tools support structured onboarding. We recommend a 1–3 church pilot before network-wide cutover.

Where do published prices appear?

List prices on this site are placeholders. Sales scopes a quote from church count, volume, and hosting. See the pricing page for tier packaging.
